From backend/app/api/routes/submissions.py (lines 260-324):

The leaderboard query currently has two ORDER BY steps:

Step 1 — SQL-level (lines 288-290):
```python
.order_by(
    best_score_sub.c.best_score.desc().nullslast(),
)
```

Step 2 — Python-level tiebreaker (lines 307-313):
```python
from itertools import groupby
sorted_rows: list = []
for _score, group in groupby(rows, key=lambda r: r[1]):
    group_list = list(group)
    group_list.sort(key=_wns_sort_key, reverse=True)
    sorted_rows.extend(group_list)
```

The fix: add `text("(runs.ppa->>'worst_negative_slack')::numeric DESC NULLS LAST")` as second
argument to `.order_by()`. The Python-side groupby+sort block becomes redundant and should be
removed after adding the SQL expression (keep the `_wns_sort_key` helper only for the return
list comprehension that reads the wns value per row).

The `text` import is already available: `from sqlalchemy import select, func, text` — confirm
before assuming (grep the file header).

SQLite test compatibility: SQLite does NOT support `->>` JSON operator, so the text() expression
will cause test failure if run against SQLite. The existing test DB is SQLite (see conftest.py).
Resolution: wrap the text() ORDER BY in a dialect check, OR move the Python sort to be a
secondary fallback only when the DB driver is sqlite. The simplest approach that satisfies both:

```python
from sqlalchemy import select, func, text
from sqlalchemy.ext.asyncio import AsyncSession

# Inside get_leaderboard():
# Detect dialect to conditionally apply SQL-level WNS sort
dialect = db.bind.dialect.name if db.bind else "sqlite"
wns_order = (
    text("(runs.ppa->>'worst_negative_slack')::numeric DESC NULLS LAST")
    if dialect == "postgresql"
    else None
)

order_clauses = [best_score_sub.c.best_score.desc().nullslast()]
if wns_order is not None:
    order_clauses.append(wns_order)

stmt = (
    select(...)
    .order_by(*order_clauses)
)
```

Then keep the Python-side groupby+sort as fallback for when `wns_order is None` (SQLite path).
This satisfies both: PostgreSQL uses the index; SQLite tests continue to pass.

IMPORTANT: `db.bind` may be None in async sessions. Use:
```python
dialect_name = db.get_bind().dialect.name
```
or access via `db.sync_session.bind.dialect.name` — check what works for the async session
in this codebase (see how other routes check the dialect, or use a try/except fallback to "sqlite").
A simpler approach: check an env var or `DATABASE_URL` setting:
```python
from app.core.config import settings
is_postgres = settings.DATABASE_URL.startswith("postgresql")
```
This is the most reliable approach — no dialect inspection on the session object needed.
