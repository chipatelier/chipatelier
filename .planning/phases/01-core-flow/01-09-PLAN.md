# Plan 01-09: ORFS Invocation + Metrics Key Gap Closure

**Phase:** 01 — Core Flow
**Wave:** 7
**Type:** Gap closure — fixes 7 critical implementation gaps identified vs CLAUDE.md spec

---

## Context

Seven critical gaps exist between the current implementation and the verified ORFS behavior
documented in CLAUDE.md. None of these are caught by the test suite because tests use mock
data with the same wrong key names. All gaps would surface immediately on first real container run.

**GAP 1** — WORK_HOME missing from Make invocation → all ORFS output goes to read-only flow dir → container crash
**GAP 2** — Wrong metrics keys → DRC always 0, flow_complete always False in production
**GAP 3** — Stage detection uses content patterns → CLAUDE.md says use `Running *.tcl, stage` from flow.sh
**GAP 4** — PDK_ROOT volume mount → ORFS doesn't use external PDK; mount fails if /data/pdks missing
**GAP 5** — GRT failure not detected → congestion failure exits 0; job marked complete when failed
**GAP 6** — read_only=True + tmpfs 512m → ORFS writes outside /workspace; too small for synthesis
**GAP 7** — target_stage never read from DB or passed to Make → every job runs same default target

<task id="09-01">
  <title>Fix run_container() — WORK_HOME, target stage, no PDK, read_only=False, tmpfs=2g</title>
  <file>worker/container/manager.py</file>
  <wave>1</wave>

  **What to change in `run_container()`:**

  1. **Remove `pdk_root` parameter** — ORFS bundles all PDKs inside the image at
     `/OpenROAD-flow-scripts/flow/platforms/`. No external PDK mount is needed or correct.

  2. **Fix the Make command** — replace `-C` with `--file` and add `WORK_HOME`:
     ```python
     command=[
         "make",
         "--file=/OpenROAD-flow-scripts/flow/Makefile",
         "DESIGN_CONFIG=/workspace/config.mk",
         "WORK_HOME=/workspace",
         target,   # e.g. "route", "finish" — new parameter
         # locked params appended as "KEY=VALUE" strings (new parameter)
         *locked_args,
     ],
     ```

  3. **Add `target: str` and `locked_args: list[str]` parameters** to `run_container()` signature.

  4. **Change `read_only=False`** — CLAUDE.md: "Do NOT use `--read-only` on the container root —
     OpenROAD may write temp files outside WORK_HOME; security is provided by `--network none` +
     cgroup limits instead."

  5. **Increase tmpfs size** — from `"size=512m"` to `"size=2g"`. CLAUDE.md recommends 2g
     because Yosys uses /tmp during synthesis.

  6. **Remove the PDK volume entry** from the volumes dict. Keep only the workspace mount.

  7. **Warm pool containers** — `warm_pool.py` pre-starts containers without a command. Those
     containers are claimed and the Make command is run via `exec_run()` in orfs_job.py when the
     warm container is used. The `run_container()` signature change is for cold-start only — do
     NOT break the warm-pool claim path in warm_pool.py itself.

  **Updated signature:**
  ```python
  def run_container(
      self,
      run_id: str,
      image: str,
      workspace_path: str,
      target: str,
      locked_args: list[str],
      settings: dict[str, Any],
  ) -> Any:
  ```

  **Verification:**
  ```bash
  grep "WORK_HOME=/workspace" worker/container/manager.py  # must be present
  grep "pdk_root\|/data/pdks\|/pdks" worker/container/manager.py  # must be absent
  grep "read_only" worker/container/manager.py  # must not appear with True
  grep "size=2g" worker/container/manager.py  # must be present
  ```

  ```python
  # Pattern: "Running floorplan.tcl, stage 2_1_floorplan"
  STAGE_LINE_PATTERN = re.compile(r"Running (\S+\.tcl), stage (\S+)")

  # Map stage_id prefix to friendly name for UI display
  STAGE_ID_TO_NAME: dict[str, str] = {
      "1_": "SYNTHESIS",
      "2_": "FLOORPLAN",
      "3_": "PLACEMENT",
      "4_": "CTS",
      "5_1_grt": "GLOBAL ROUTE",
      "5_2": "DETAIL ROUTE",
      "6_": "FINISH",
  }
  ```

  In the log streaming loop, replace the old pattern loop:
  ```python
  m = STAGE_LINE_PATTERN.search(line)
  if m:
      stage_id = m.group(2)  # e.g. "2_1_floorplan"
      # Determine friendly name
      stage_name = next(
          (name for prefix, name in STAGE_ID_TO_NAME.items() if stage_id.startswith(prefix)),
          stage_id.upper()
      )
      separator = SEPARATOR_FMT.format(stage=stage_name)
      publish_line(separator)
      update_status("running", stage_id)
  ```

  ### Fix D: GRT failure detection

  After container exits (after line ~214), check for the GRT failure indicator before
  setting `final_status`:

  ```python
  exit_code = result.get("StatusCode", 1)

  # GRT congestion failure: exit code may be 0 but 5_1_grt-failed.odb is written
  # instead of 5_1_grt.odb. Must check for this file explicitly.
  # Path requires PLATFORM and DESIGN_NAME parsed from config.mk or derived from run.
  grt_failed = _check_grt_failure(workspace)
  if grt_failed:
      final_status = "failed"
      publish_line("[chipatelier] GRT congestion failure detected (5_1_grt-failed.odb found) — marking failed")
  else:
      final_status = "complete" if exit_code == 0 else "failed"
  ```

  Add helper function:
  ```python
  def _check_grt_failure(workspace: str) -> bool:
      """Return True if GRT congestion failure ODB exists in the workspace.

      ORFS global route can fail with congestion but exit 0. It writes
      5_1_grt-failed.odb instead of 5_1_grt.odb in this case.
      Use glob to find it without needing PLATFORM/DESIGN_NAME.
      """
      import glob as glob_mod
      pattern = os.path.join(workspace, "results", "*", "*", "base", "5_1_grt-failed.odb")
      return bool(glob_mod.glob(pattern))
  ```

  <file>backend/app/services/metrics_service.py</file>

  **Three key name corrections required** (CLAUDE.md "Real ORFS Metrics Schema" is authoritative):

  ### WNS/TNS fallback keys

  The partial-run fallback (when finish stage not yet complete) uses global route metrics.
  The JSON file is `5_1_grt.json` and its keys use `globalroute__` prefix — NOT `route__`.

  ```python
  # WRONG (current):
  "worst_negative_slack": stage_metrics.get(
      "route__timing__setup__ws",          # does not exist
      stage_metrics.get("finish__timing__setup__ws"),
  ),

  # CORRECT:
  "worst_negative_slack": stage_metrics.get(
      "finish__timing__setup__ws",          # primary: full flow signoff
      stage_metrics.get("globalroute__timing__setup__ws"),  # fallback: partial run
  ),
  ```

  Apply same fix to `total_negative_slack`:
  ```python
  "total_negative_slack": stage_metrics.get(
      "finish__timing__setup__tns",
      stage_metrics.get("globalroute__timing__setup__tns"),
  ),
  ```

  ### DRC violation count

  `finish__design__violations` does NOT exist in real ORFS output (CLAUDE.md: "CRITICAL").
  DRC routing errors come from detail route: `detailedroute__route__drc_errors`.

  ```python
  # WRONG (current):
  "drc_violations": int(stage_metrics.get("finish__design__violations", 0) or 0),

  # CORRECT:
  "drc_violations": int(stage_metrics.get("detailedroute__route__drc_errors", 0) or 0),
  ```

  ### flow_complete detection

  Since `finish__design__violations` never exists, `flow_complete` is always `False` in
  production. Use a key that IS written by `final_report.tcl` — `finish__power__total`
  or `finish__timing__setup__ws` both work:

  ```python
  # WRONG (current):
  "flow_complete": stage_metrics.get("finish__design__violations") is not None,

  # CORRECT:
  "flow_complete": stage_metrics.get("finish__timing__setup__ws") is not None,
  ```

  Also fix the docstring comment at line 5 that lists `finish__design__violations` as an
  example key — replace it with a correct example.
